Why we trust this number
The first full sweep on this device only logged pass/fail correctness, not the per-shape error margins our earlier runs always carried — so we didn't call it confirmed yet. We re-ran the identical, unmodified candidate specifically to capture the full per-shape max_abs / max_rel breakdown. Result: 5.40× / 6.54×, within 1.3% of the first run — the same number, now with the evidence attached.
What we ruled out, and why

A dead end explained is worth more than a claim untested

Rejected
Pretransposed Linear weights
Won standalone (+80%). Regressed 10–44% stacked on CUDA-graph routes — an extra kernel launch per call outweighed the layout win.
Rejected
Native fp16 weights
Correctness failed 2.5–5.8× over tolerance. Root cause found: autocast keeps the residual stream fp32 the whole time — native fp16 doesn't.
Understood
Why autocast can't be "beaten"
Replicating its exact safety semantics by hand means reconstructing autocast itself — there's no free win left there.
